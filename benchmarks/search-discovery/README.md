# Brand-blind search discovery benchmark

This benchmark measures whether search products surface a suitable public
clinical variant interpretation MCP when the query does not name Folklore or
Helena Bioinformatics. It is separate from the agent discovery benchmark,
which tests installed skill selection and tool routing.

## Claim boundary

A result can establish visibility, citation, recommendation and official-page
reach for one recorded provider, product, locale and run. It cannot establish
clinical accuracy, market leadership, causal ranking improvement or universal
agent behavior.

## Corpus

`queries.csv` contains 60 stable queries in six equal cohorts:

1. exact category;
2. capability plus MCP;
3. task first without MCP;
4. concrete public variant;
5. alternative selection;
6. safety and control.

Every row has a stable ID, intent, expected capability, forbidden brand terms,
baseline locale and pass condition. Do not edit this file between baseline and
rerun. New queries belong in a separately versioned cohort.

## Raw ledger

Copy `ledger-template.csv` for each measurement window. Record one row per
query and provider run. Keep provider, product, model, search mode, country,
language and timestamp distinct. Preserve source URLs and a path to raw
evidence such as exported results or screenshots.

The visibility fields are independent booleans:

- `visible`: the product appears in the observed result set;
- `mentioned`: the product is named in an answer or result;
- `cited`: a result cites a Folklore or Helena controlled source;
- `recommended`: the result recommends the product for the task;
- `selected`: an agent chooses it for execution;
- `official_page_reached`: the path exposes the canonical task page;
- `independent_source`: a supporting source is not Helena controlled.

A blank rank means not ranked or not applicable. Do not convert a directory
submission, open issue or self-authored listing into independent acceptance.

## Summary

Run the summarizer with a filled ledger path:

    python3 benchmarks/search-discovery/summarize.py evidence/search-ledger.csv

The command validates IDs and field types, then emits separate rates for each
provider, locale and query cohort. It never combines the rates into one score.

## Reproducibility rules

- Use a clean session for every query.
- Keep query text, ordering and pass rules unchanged for the rerun.
- Record personalization and location controls when the provider exposes them.
- Retain raw evidence even when Folklore is absent.
- Report unavailable providers as unavailable, not as negative results.
- Allow a declared indexation interval before the identical rerun.
- Report new queries and translated queries as separate cohorts.
- Keep search discovery separate from MCP connection and clinical evaluation.
